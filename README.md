# 物探しカメラ（試作）

なくす前に品物を撮っておき、なくしたらスマホを部屋にかざして探すアプリ。
写真も判定もスマホの中だけで済み、外へは送らない。

## 使い方

1. 「品物を登録する」で品物を3〜5方向から撮り、枠で囲む
2. なくしたら「探す」を押して、部屋にゆっくりかざす
3. 似た物が映ると黄色い枠と音、確かになると「これですか？」が出る
4. 違うときは「違う」を押すと、同じ物に反応しにくくなる

感度は 控えめ／ふつう／敏感 から選べる。カメラのない PC では「写真で試す」が使える。

## パソコンで動かす

```bash
cd C:\add\claudecode\monosagashi
```

```bash
node tools/serve.mjs
```

http://127.0.0.1:8750/ を開く。スマホのカメラは https でないと使えないので、スマホで試すには https の場所へ置く必要がある（GitHub Pages など）。

## アイコン

- 絵は `icon.svg`（カメラの枠の中で鍵が見つかった図）。ブラウザのタブ用は、印と光を省いて線を太くした `favicon.svg`。
- スマホのホーム画面用などの PNG は `icons/` にある。絵を変えたら、次のコマンドで出る URL をブラウザで開いて作り直す。

```bash
cd C:\add\claudecode\monosagashi
```

```bash
node tools/make-icons.mjs
```

## 仕組み

- 画像AI DINOv2 small（量子化版 24MB）を onnxruntime-web でブラウザ内で動かす（`js/worker.js`）
- 登録：写真を小さなマス（14×14px）ごとの特徴にし、枠の中を手本、外を背景として覚える（`buildProfile`）
- 探す：映像の各マスを手本と比べて似ている場所を出し、そこを切り抜いて確かめる（`scanRegion`）
- 映像全体と中央の拡大を交互に調べる。近い場所で続けて反応したら「見つかった」とする（`judge`）
- 境目は、調べ続けて分かった部屋の普段の点の高さに合わせて下げる（`thresholdFor`）

## 判定の試験

`test/bench.html`（開発用）。品物を切り抜いて部屋の写真へ貼り、見つけられるか・品物がないのに反応しないかを数える。
試験画像は COCO val2017 から取った手元の写真で、このフォルダには入れていない。

2026-11-06 の結果（登録写真は1枚、1枚の画像を調べた結果。重みと境目を決めた後に別の並びで確認）：

| 感度 | 品物なしの部屋で反応 | 品物の幅が画面の30% | 18% | 10% |
|---|---|---|---|---|
| 控えめ | 1/70 | 23/28 | 18/28 | 7/28 |
| ふつう | 2/70 | 24/28 | 20/28 | 7/28 |
| 敏感 | 8/70 | 26/28 | 22/28 | 9/28 |

ふつうの品物ごと（12枚中）：青りんご12、マグ10、スマホ9、ネクタイ7、ぬいぐるみ6、靴6、市松の旗1。

- 品物を平面のまま貼っただけで、実物を別の方向から撮ってはいない。実機の成績はこれより下がるはず
- 無地でも色が目立てば見つかり、規則的な模様（市松）は苦手だった。柄があれば有利とは言えない
- 複数枚の登録、動かしながらの連続判定の効果は、この試験では測っていない
- 1回の判定はこのPCで約0.7秒（4スレッド）。スマホの速さは未測定

## 確かめたこと・まだのこと

- 確かめた：登録（枠の調整を含む）・保存・写真で試す・「違う」で別の物への反応が消えること（カメラは映像を流し込む方法で代用）・スマホの幅の画面・GitHub Pages と同じ条件（見出しなし）で sw.js が複数スレッドを有効にすること
- まだ：本物のスマホのカメラ、実物の品物、スマホでの速さ、振動と音、ライト
- 登録した品物そのものを「違う」と答えても、そっくりなので反応は消えない

node tools/serve.mjs 8750 --images=<coco フォルダの親>
